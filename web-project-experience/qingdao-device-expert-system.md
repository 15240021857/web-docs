## 架构组成
### 前端交互展示层
分为三类入口：业务管理后台、2D 电网一张图大屏、轻量化三维 / 单线图模块
1. 业务 Web 后台：全寿命台账维护、状态评价查看、缺陷管理、报表查询、系统配置；
2. 2D 电网一张图大屏：基于 OpenLayers SDK 开发，电网拓扑、站点 / 设备点位展示、设备健康状态着色、点击查看全寿命评价结果、统计看板；
3. 轻量化三维 & 电缆单线图
Three.js 变压器设备模型独立页面，通过iframe嵌入主系统；仅单设备三维模型，不是全站大场景；
电缆单线图：电缆拓扑、分段、状态可视化展示；
三维是隔离子页面，iframe 嵌套，和主 Vue 应用解耦，规避 Three.js 大库对主工程的冲击。
### 前端内部架构分层
- 技术栈：Vue3 + TS + Vite；OpenLayers 电网一张图；Three.js 独立 iframe 子应用；ECharts 图表；无 Cesium/Mars3D。
1. 页面应用层
- 业务后台页面：台账、评价、缺陷、统计报表、系统配置
- 电网一张图大屏页面（OpenLayers 主页面）：电网拓扑、设备点位、图层控制、弹窗详情、大屏统计看板
- 内嵌页面容器：iframe容器组件，加载独立 Three.js 变压器模型页面、电缆单线图页面
页面只做拼装、交互，不写复杂计算、图元处理逻辑。
2. 业务组件层
- 通用二次封装组件：表单、表格、弹窗、分页、附件上传等
- 电力业务组件：设备树组件、全寿命履历时间线组件、状态评价卡片、风险告警组件、统计仪表盘
- 地图业务组件：OpenLayers 封装组件、图层管理组件、设备弹窗卡片、搜索定位组件
- iframe 容器封装组件：处理子页面通信、传参、消息监听
3. Composables/Hooks 业务逻辑层
把业务逻辑抽离，和 DOM 解耦
- 设备全寿命 hook：设备查询、履历组装、评价结果处理
- 电网地图 hook：地图初始化、图层管理、设备点位渲染、点击定位、高亮、筛选
- iframe 通信 hook：主应用和 iframe 内 Three.js 子页面消息交互，参数传递、事件通知
- 图表 hook：ECharts 统计图表数据处理、实例销毁
- 告警风险 hook：风险数据处理
注意：Three.js 的所有逻辑全部放在 iframe 独立子项目内部，主项目不直接引入 Three.js，主项目仅通过 postMessage 和子页面通信。
4.API 服务层
- axios 统一封装：拦截器、token、错误处理
- 按业务拆分 api 模块：pmsSyncApi.ts、deviceLifeApi.ts、evaluateApi.ts、mapApi.ts
- 调用后端接口获取从 PMS 同步过来的设备台账、履历、评价结果；
- 获取电网一张图图元、坐标、拓扑数据；
- iframe 子页面单独有自己的 api 层，独立请求设备模型、设备详情数据。
5. 公共工具 & 状态层
- utils：电力数据格式化、时间处理、树结构处理、地图工具函数、postMessage 通信工具
- constants：设备类型、评价等级、风险等级等电力枚举常量
- Pinia 全局状态：用户信息、全局设备筛选条件、地图全局状态
- TS 类型定义：设备台账、全寿命履历、状态评价、地图图元整套 TS 类型
- 第三方 SDK 隔离层：对 OpenLayers 做上层封装，隔离原始 OpenLayers API，业务代码尽量不直接操作原生 OpenLayers 对象。
6. 工程底层（Vite 工程层）
- Vue‑router 动态路由、权限控制（页面 + 按钮权限）
- vite 配置：分包构建；OpenLayers、ECharts 按需引入；Three.js 完全放在另外独立工程，主包不引入 Three.js，减小主项目打包体积；环境变量；gzip 压缩
- ESLint、Prettier、TS 类型校验，代码规范
